# Service Info

## Common use cases

The Stormshield Network Security (SNS) integration allows organizations to ingest high-fidelity security logs from SNS firewalls into the Elastic Stack for centralized visibility, long-term retention, and advanced threat hunting.
- **Network Traffic Monitoring:** Gain deep visibility into allowed and denied traffic across the network perimeter by analyzing connection and NAT logs.
- **Security Incident Investigation:** Rapidly investigate potential breaches by correlating intrusion prevention and detection system (IPS/IDS) alarms with other security telemetry in Elastic Security.
- **Compliance and Auditing:** Maintain a comprehensive audit trail of administrative changes and system events on the SNS appliance to meet regulatory requirements and internal security policies.
- **Web Activity Analysis:** Monitor and analyze web filtering logs to identify risky browsing behavior or potential data exfiltration attempts through non-standard web channels.

## Data types collected

This integration collects log data from Stormshield SNS appliances through the **Stormshield SNS logs** policy template, which includes the following data streams:

- **Stormshield logs (via UDP)**: Collect Stormshield logs (via UDP). This is the standard method for high-performance log transmission where minimal overhead is required.
- **Stormshield logs (via TCP)**: Collect Stormshield logs (via TCP). This method is preferred when reliable delivery is required over network performance.

The following specific information types are extracted from these streams:
- **Firewall Logs:** Information on traffic allowed or blocked by filter rules, including NAT translations and connection states.
- **Audit/Administration Logs:** Detailed records of administrative actions performed on the SNS appliance, such as configuration changes (serverd logs).
- **Security Events:** Logs generated by security engines, including intrusion prevention (IPS), alarms, antivirus, and vulnerability detection.
- **VPN Logs:** Data regarding encrypted tunnel establishments and activity for remote access or site-to-site connections.
- **Data Format:** Events are typically received in Syslog format (supporting RFC5424 or legacy formats).

## Compatibility

The **Stormshield Network Security (SNS)** integration is compatible with the following:
- **SNS v4 and above:** The integration is designed to support firmware versions from v4 onwards.
- **Elastic Stack:** Requires Kibana version **^8.11.4** or **^9.0.0**.
- **Integration Version:** 1.4.0.
- **Syslog Formats:** Supports both RFC5424 and legacy syslog formats as provided by the SNS appliance.

## Scaling and Performance

To ensure optimal performance in high-volume environments, consider the following:
- **Transport/Collection Considerations:** Users can choose between UDP and TCP for log transport. **UDP** (default port `514`) offers lower overhead and is suitable for high-volume environments where occasional packet loss is acceptable. **TCP** (default port `601`) is recommended for environments requiring guaranteed delivery of security logs, though it introduces slightly more overhead on the appliance and the network.
- **Data Volume Management:** To manage data volume, administrators should selectively enable log categories on the SNS appliance. While "Verbose (filter log)" provides the most detail for firewall rules, it can generate massive amounts of data; it is recommended to apply this setting only to critical rules or during active troubleshooting to prevent ingest saturation. Configure the SNS appliance to forward only necessary events (e.g., severity level 6 or lower) to reduce the load on the ingest pipeline.
- **Elastic Agent Scaling:** For high-throughput environments processing logs from multiple large-scale SNS appliances, deploy multiple Elastic Agents behind a network load balancer to distribute traffic evenly. Place Agents close to the data source to minimize latency and monitor the Agent's CPU and memory usage to ensure it can keep up with the incoming syslog stream without dropping packets.

# Set Up Instructions

## Vendor prerequisites

- **Administrative Access:** You must have administrative credentials for the Stormshield SNS web administration interface to configure notification profiles and security policies.
- **Network Connectivity:** The SNS appliance must be able to reach the Elastic Agent host over the network via the configured syslog port (typically UDP `514` or TCP `601`).
- **Host Object Configuration:** A "Host" object representing the Elastic Agent's IP address must be created in the SNS appliance's object database.
- **System Licenses:** Ensure the SNS appliance has the necessary licenses active for the security modules (IPS, Web Filtering, etc.) whose logs you wish to collect.

## Elastic prerequisites

- **Elastic Agent:** An Elastic Agent must be installed and successfully enrolled in Fleet.
- **Integration Policy:** The Stormshield SNS integration must be added to the Agent policy assigned to the listener host.
- **Port Availability:** The configured syslog ports (`514` or `601`) must be open and not in use by other services on the Elastic Agent host.

## Vendor set up steps

### For Syslog Collection (TCP or UDP):
1. Log in to your **Stormshield SNS web administration interface**.
2. Navigate to **Configuration > Notifications > Logs - Syslog - IPFIX**.
3. Select the **Syslog** tab to manage remote logging profiles.
4. Enable a new Syslog profile by double-clicking its status in the profile list on the left-hand side.
5. Configure the profile with the following parameters:
    * **Name**: Provide a descriptive name, such as `ElasticAgent_Syslog`.
    * **Syslog server**: Select the host object that corresponds to the IP address of the server where the Elastic Agent is installed.
    * **Protocol**: Choose either `TCP` or `UDP`. Ensure this matches your Elastic Agent configuration.
    * **Port**: Enter the port number (e.g., `514` for UDP or `601` for TCP).
    * **Format**: Select `LEGACY-LONG` or `RFC5424`. `LEGACY-LONG` is often preferred for ensuring no message length limits interfere with log integrity.
6. In the **Logs enabled** table at the bottom of the screen, double-click the status for each log type you wish to forward (e.g., `Alarm`, `Connection`, `Web`, and `Filter`).
7. To ensure firewall rule logs are generated, navigate to **Configuration > Security policy > Filter - NAT**.
8. For each relevant rule, double-click the **Action** column. In the **General** tab, set the **Log level** to `Verbose (filter log)`. In the **Advanced properties** tab, ensure the Syslog profile you created is selected.
9. Click **Apply** at the bottom of the interface to save and commit the changes.

## Kibana set up steps

1. In Kibana, navigate to **Management > Integrations**.
2. Search for **StormShield SNS** and click **Add StormShield SNS**.
3. Follow the prompts to add the integration to an existing Elastic Agent policy or create a new one.
4. Configure the input types based on your vendor setup:

### Collecting logs from Stormshield SNS via UDP
This input collects Stormshield logs via the UDP protocol.
- **Listen Address** (`udp_host`): The bind address to listen for UDP connections. Set to `0.0.0.0` to bind to all available interfaces. Default: `localhost`.
- **Listen Port** (`udp_port`): The UDP port number to listen on. Default: `514`.
- **Preserve original event** (`preserve_original_event`): Preserves a raw copy of the original event, added to the field `event.original`. Default: `False`.

### Collecting logs from Stormshield SNS via TCP
This input collects Stormshield logs via the TCP protocol.
- **Listen Address** (`tcp_host`): The bind address to listen for TCP connections. Set to `0.0.0.0` to bind to all available interfaces. Default: `localhost`.
- **Listen Port** (`tcp_port`): The TCP port number to listen on. Default: `601`.
- **Preserve original event** (`preserve_original_event`): Preserves a raw copy of the original event, added to the field `event.original`. Default: `False`.

5. Click **Save and continue**. The Elastic Agent will automatically update its configuration.

# Validation Steps

After configuration is complete, verify that data is flowing correctly.

### 1. Trigger Data Flow on Stormshield:
- **Authentication event:** Log out of the Stormshield web administration interface and log back in to trigger an administration log.
- **Web traffic:** Browse several websites from a workstation located behind the SNS firewall to generate traffic and filter logs.
- **Configuration event:** Navigate to **Configuration**, make a minor change to a rule description, and click **Apply** to generate an audit event.

### 2. Check Data in Kibana:
1. Navigate to **Analytics > Discover**.
2. Select the `logs-*` data view.
3. Enter the KQL filter: `data_stream.dataset : "stormshield.log"`
4. Verify logs appear in the results. Expand a log entry and confirm these fields:
   - `event.dataset` (should be `stormshield.log`)
   - `source.ip` and/or `destination.ip`
   - `event.action` or `event.outcome`
   - `message` (the raw log payload)
5. Navigate to **Analytics > Dashboards** and search for "Stormshield SNS" to view pre-built visualizations.

# Troubleshooting

## Common Configuration Issues

- **Profile Status Disabled**: Ensure the Syslog profile status in the SNS interface is set to "Enabled". If the profile is grayed out or marked as disabled, no logs will be sent regardless of the configuration.
- **Protocol Mismatch**: Verify that the protocol selected on the SNS appliance (TCP or UDP) matches the input type selected in the Elastic Agent policy. A mismatch will prevent the Agent from correctly receiving the stream.
- **Firewall Rules Log Level**: If connection logs are missing, check the **Filter - NAT** rules. Logs are only generated for rules where the log level is explicitly set to a value like `Verbose (filter log)`.
- **Object Reference Errors**: Ensure the "Syslog server" host object in the SNS configuration correctly points to the current IP address of the Elastic Agent. If the Agent IP changes, this object must be updated.

## Ingestion Errors

- **Parsing Failures**: Check the `error.message` field in Kibana. If logs are arriving but not parsing, ensure the SNS log format is set to `LEGACY-LONG` or `RFC5424`, as other formats may not align with the integration's built-in grok patterns.
- **Timestamp Mismatches**: Ensure the time and timezone settings on the SNS appliance are synchronized with a reliable NTP source. Significant time drift can cause logs to appear outside the expected time range in Discover.
- **Dropped Events (UDP)**: If using UDP and seeing missing events during high traffic, check network statistics for packet loss or consider switching to the TCP input for more reliable delivery.
