# Service Info

## Common use cases

The Zeek integration is designed to ingest and normalize the extensive network metadata generated by the Zeek (formerly Bro) network security monitor. By transforming passive network traffic analysis into structured logs, this integration enables security teams to perform deep inspection and long-term analysis of network behavior.

- **Threat Detection and Hunting:** Utilize detailed protocol logs such as SSL/TLS handshakes, DNS queries, and HTTP headers to identify malicious patterns, command-and-control (C2) communication, or data exfiltration attempts.
- **Network Visibility and Inventory:** Leverage specialized data streams like `known_hosts`, `known_services`, and `software` to maintain a real-time inventory of active systems, the services they expose, and the versions of software running on the local network.
- **Incident Response and Forensics:** Use the `connection` and `notice` data streams to reconstruct the timeline of security incidents, allowing analysts to trace lateral movement and verify the scope of a breach.
- **Protocol Compliance Auditing:** Monitor transactions across sensitive protocols like SMB, FTP, and Kerberos to ensure compliance with internal security policies and regulatory requirements regarding data access and transfer.

## Compatibility

- **Kibana Version:** This integration requires Kibana version `^8.12.0` or `^9.0.0`.
- **Zeek Version:** This module has been developed against **Zeek** version 2.6.1, but is expected to work with various other versions that support JSON log output.
- **Operating Systems:** **Zeek** requires a Unix-like platform and is compatible with Linux, FreeBSD, and macOS.

## Scaling and Performance

To ensure optimal performance in high-volume environments, consider the following:
- **Transport/Collection Considerations:** This integration uses logfile monitoring via the Elastic Agent. Collection performance is directly tied to the local disk I/O speed of the Zeek sensor and the Agent's ability to read from the filesystem. It is critical to configure log rotation within Zeek (via `zeekctl`) to prevent files from growing indefinitely, which can degrade read performance.
- **Data Volume Management:** Zeek is a high-volume generator. To manage ingest load, configure Zeek scripts to filter unneeded traffic at the source. Within the Elastic Agent policy, you can selectively disable high-volume data streams (such as `dns` or `ssl`) if they are not required for your specific security or monitoring use cases.
- **Elastic Agent Scaling:** For large-scale deployments featuring multiple Zeek sensors, deploy a dedicated Elastic Agent on each sensor node. Ensure each node has sufficient CPU and memory allocated for JSON parsing. In extreme throughput scenarios, consider distributing log files across multiple disk paths and using multiple Agent instances to parallelize ingestion.

# Set Up Instructions

## Vendor prerequisites

- **Zeek Installation:** A functional installation of Zeek on a supported Unix-like operating system.
- **Administrative Access:** Root or sudo permissions are required to modify Zeek configuration files (`local.zeek`) and restart services.
- **JSON Logging Policy:** The `policy/tuning/json-logs.zeek` script must be available within the Zeek installation's script directory.
- **File System Permissions:** The user account running the Elastic Agent must have read access to the directory where Zeek writes its logs (e.g., `/opt/zeek/logs/`).
- **Disk Space:** Ensure adequate disk space is available for the JSON-formatted logs, as JSON can be more verbose than the default TSV format.

## Elastic prerequisites

- **Elastic Agent Installation:** The Elastic Agent must be installed on the same host as Zeek (or a host with access to the shared log directory) and enrolled in Fleet.
- **Kibana Version:** Ensure your Elastic Stack is running version `8.12.0` or higher.
- **Network Connectivity:** The Elastic Agent requires outbound network connectivity to the Elastic Stack (Elasticsearch and Kibana) on port 443 or 9200/9243.
- **Permissions:** The user running the Elastic Agent must have read permissions for the Zeek log directories (e.g., `/opt/zeek/logs/current/`).

## Vendor set up steps

### For Logfile Collection:
1. **Identify the Configuration Path:** Locate your `local.zeek` file. This is commonly found at `/opt/zeek/share/zeek/site/local.zeek` or `/usr/local/zeek/share/zeek/site/local.zeek`.
2. **Enable JSON Output:** Open `local.zeek` in a text editor (e.g., `sudo nano /opt/zeek/share/zeek/site/local.zeek`) and append the following line to the end of the file:
   ```
   @load policy/tuning/json-logs.zeek
   ```
3. **Verify the Script:** Ensure the script exists in your environment. You can check this by running `find /opt/zeek -name json-logs.zeek`.
4. **Apply Configuration:** Use the Zeek control utility to deploy the changes and restart the process:
   ```sh
   zeekctl deploy
   ```
   If Zeek is not managed by `zeekctl`, restart the service using your system's service manager (e.g., `systemctl restart zeek`).
5. **Confirm JSON Format:** Navigate to your log directory (e.g., `/opt/zeek/logs/current/`) and inspect a log file like `conn.log`. Ensure the lines start with `{` and are valid JSON objects.
6. **Set Permissions:** Ensure the Elastic Agent user can read the logs. If the agent runs as `elastic-agent`, you may need to add it to the group that owns the logs:
   ```sh
   sudo usermod -aG zeek elastic-agent
   chmod -R g+r /opt/zeek/logs/current/
   ```

## Kibana set up steps

1. In Kibana, navigate to **Integrations** > **Zeek**.
2. Click **Add Zeek**.
3. Follow the prompts to add the integration to an existing Elastic Agent policy or create a new one.
4. Configure the global **Base Path** (`base_paths`) to specify where the Zeek log files are located. Default values include:
   - `/var/log/bro/current`
   - `/opt/zeek/logs/current`
   - `/usr/local/var/spool/zeek`
5. Review the specific data stream configurations under the input section.
6. Save the integration. The Elastic Agent will automatically update its configuration.

# Validation Steps

After configuration is complete, verify that data is flowing correctly.

### 1. Trigger Data Flow on Zeek:
- **Generate DNS Traffic:** Perform several DNS lookups from a monitored system (e.g., `dig elastic.co` or `nslookup google.com`).
- **Generate HTTP Traffic:** Use `curl` to fetch a webpage to trigger HTTP and connection logs (e.g., `curl -I http://www.elastic.co`).
- **Generate Authentication Events:** Log in and out of the Zeek host via SSH to trigger `ssh` and `connection` logs.
- **Generate Discovery Data:** Wait for the `known_hosts` or `known_services` logs to update as Zeek identifies active systems on the network.

### 2. Check Data in Kibana:
1. Navigate to **Analytics > Discover**.
2. Select the `logs-*` data view.
3. Enter the KQL filter: `data_stream.dataset : "zeek.connection"`
4. Verify logs appear. Expand a log entry and confirm these fields:
   - `event.dataset` (should be `zeek.connection`)
   - `source.ip` and `destination.ip`
   - `event.action` or `zeek.connection.state`
   - `message` (the raw log payload)
5. Navigate to **Analytics > Dashboards** and search for "Zeek" to view the pre-built dashboards for overview, DNS, and HTTP traffic.

# Troubleshooting

## Common Configuration Issues

- **Logs Remain in TSV Format**: If logs are still tab-separated, the `@load policy/tuning/json-logs.zeek` line may not be in the correct `local.zeek` file or Zeek was not restarted with `zeekctl deploy`.
- **Permission Denied for Agent**: The Elastic Agent often runs as a service user. If it cannot read `/opt/zeek/logs/current/`, ingestion will fail. Ensure the directory and file permissions allow the Agent user read access.
- **Incorrect Path Configuration**: If the integration is configured to look in `/var/log/bro/current` but Zeek is installed in `/opt/zeek/`, no logs will be ingested. Verify the `filenames` variable in Kibana matches the actual disk path.
- **Zeek Process Not Running**: If no logs are being written to disk, check the status of Zeek using `zeekctl status` to ensure the capture process is active.

## Ingestion Errors

- **Parsing Failures**: If logs appear in Kibana but fields are not mapped, check the `error.message` field. This often happens if the JSON is malformed or if the log file contains mixed formats (e.g., old TSV lines followed by new JSON lines).
- **Field Mapping Mismatches**: Ensure that the `event.original` field is enabled if you need to debug how the integration is mapping specific Zeek JSON keys to ECS (Elastic Common Schema) fields.
- **Log Rotation Issues**: If logs stop arriving periodically, check if the Agent is following the rotated files correctly. Ensure the file pattern (e.g., `*.log`) includes the active log file and not just archived/compressed versions.
